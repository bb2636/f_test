# 자재비 사용자 편집은 자동저장 경로에 연결돼 있어야 한다

자재비 섹션(MaterialCostSection)을 부모에서 `onRowsChange={setMaterialRows}`(raw setter)로
마운트하면, 사용자가 자재항목을 골라도 자동저장 스케줄러(triggerAutoSaveAfterSync)를
전혀 타지 않는다. 자동저장은 sync 지점(복구면적 변경/탭 진입/노무비)과 명시 저장 버튼에서만
발동하므로, 사용자가 저장 없이 단계(현장보고→복구완료보고/청구)를 넘기면 선택값이 DB에
남지 않는다.

**Why:** 단계 전환 시 서버가 견적(estimate.n = materialCostData)을 sourceEstimate에서
복사/재로드한다. 미저장 선택값은 복사본/재하이드레이션에서 빈 값으로 사라진다(증상: 고른
자재명이 빈 "선택"으로 되돌아감).

**How to apply:**
- 자재비 editable 마운트의 onRowsChange는 set + `triggerAutoSaveAfterSync("material:userEdit")`
  하는 래퍼를 써라. 스케줄러가 1500ms 디바운스 + 해시변경감지 + 가드(readOnly/미수화/저장중/
  파트너 차단)를 적용하므로 과도저장/루프 위험은 낮다. readonly(견적서) 마운트는 가드가
  자동저장을 막으므로 raw setter로 둬도 무방.
- 인라인 자재항목 입력부(직접입력 onChange, 드롭다운 Select)는 공용 updateRow와 동일하게
  `isAutoGenerated` 행이면 `isItemOverridden=true`를 박아야 syncMaterialFromRecoveryArea
  재계산에서 사용자 선택이 보존된다(보존 계약 전제).
- 잔여 한계: 선택 직후 1.5초 이내 즉시 단계 이탈/새로고침은 디바운스 만료 전이라 경합 가능.
  '절대 보장'이 필요하면 단계 전환 직전 autosave flush(강제 1회 저장) 추가가 최종 안전장치.
