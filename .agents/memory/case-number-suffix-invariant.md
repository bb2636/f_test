# 접수번호 suffix 는 케이스 종류의 식별자

접수번호 형식: `{prefix}-{suffix}`. **suffix===0 = 손해방지(손방), suffix>=1 = 피해세대(대물)**.

- 문서/PDF 생성(`server/pdf-lib-service.ts`)이 `suffix === 0` 분기로 손해방지/피해세대 레이아웃을 결정함(주소: -0=피보험자 주소, -N=피해자 주소 / 섹션 헤더 "복구방식" vs "피해 복구방식" 등 10여 곳).
- 따라서 **한 사고건(prefix)당 손해방지(-0)는 단 1개만** 존재할 수 있음. 손해방지 건을 -1 등 다른 번호로 옮기면 문서가 피해세대로 오분류됨(주소·헤더 전부 어긋남).

**Why:** 같은 보험사고번호로 재접수 시 `getNextCaseSequence`가 기존 prefix를 재사용함. "손해방지만" 생성 경로가 `getPreventionCaseByPrefix` 가드 없이 `${prefix}-0`을 다시 만들면 DB UNIQUE 충돌(23505) → 409 "접수번호가 중복되었습니다"(원인 불명처럼 보이는 회귀). "둘 다(손방+대물)" 경로는 가드가 있어 정상이라 증상이 헷갈림.

**How to apply:** `${prefix}-0`을 새로 만드는 모든 "손해방지-only 신규생성" 경로(POST /api/cases 의 배당대기 draft 생성 + 접수완료 즉시생성)는 생성 전 `getPreventionCaseByPrefix(prefix)`로 기존 -0 존재를 확인. 존재하면 케이스를 만들지 말고 명확한 409 메시지 반환(사용자 합의: 자동 재번호 금지=문서 오분류, 안내 후 중단이 정답). 기존 -0 덮어쓰기/번호 재배정은 종류 오분류·데이터 손상 위험이라 금지. 수정은 "이어서 작성하기"(editCaseId)로만.
