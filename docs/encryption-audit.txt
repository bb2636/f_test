1. 비밀번호 (Password)
────────────────────────────────────────────────────────────────────────────────

  대상            비밀번호 (users.password)
  방식            bcrypt 해시 (salt rounds = 10)
  적용 위치       server/storage.ts — createUser(), updatePassword(), seedTestUsers()
  실제 암호화     ✅ 예 (단방향 해시, 복호화 불가)
  DB 저장 형태    "$2b$10$..." (bcrypt 해시 문자열)
  검증 방식       bcrypt.compare() — server/storage.ts verifyPassword()
  API 응답 제외   ✅ 예 — routes.ts에서 { password, ...rest } 구조분해로 제거
  비고            - 모든 사용자 생성/수정 시 bcrypt.hash(password, 10)
                  - API 응답에 password 필드 미포함 (라우트별 수동 제거)

2. 개인정보 PII 암호화 — users 테이블
────────────────────────────────────────────────────────────────────────────────

  ┌─────────────────┬─────────────────┬─────────────────┬──────────┬──────────┐
  │ 대상 (평문컬럼)  │ 암호화 컬럼      │ 해시 컬럼        │ 실제암호화│ 비고     │
  ├─────────────────┼─────────────────┼─────────────────┼──────────┼──────────┤
  │ email           │ email_enc       │ email_hash      │ ✅ 예    │ SHA-256  │
  │ phone           │ phone_enc       │ phone_hash      │ ✅ 예    │ SHA-256  │
  │ address         │ address_enc     │ —               │ ✅ 예    │          │
  │ address_detail  │ address_detail_enc │ —            │ ✅ 예    │          │
  └─────────────────┴─────────────────┴─────────────────┴──────────┴──────────┘

  방식            AES-256-GCM 대칭키 암호화
  저장 형태       {IV(base64)}:{AuthTag(base64)}:{Ciphertext(base64)}
  적용 위치       server/pii-service.ts — encryptUserFields() / decryptUserFields()
                  server/storage.ts — createUser(), updateUser(), getUser(), getAllUsers()
  해시 용도       이메일/전화번호 중복 체크 (정규화 후 SHA-256)
  환경변수        PII_ENCRYPTION_KEY (64자 hex = 32바이트)
  비활성화 가능   ✅ 예 — PII_ENCRYPTION_KEY 미설정 시 평문 모드
  API 응답 제외   ✅ 예 — _enc/_hash 컬럼은 stripPiiFromResponse()에서 재귀 제거
  비고            - 과도기: 평문 컬럼 + 암호화 컬럼 병행 유지
                  - 읽기: _enc 복호화 우선, 없으면 평문 fallback
                  - 쓰기: 평문 + _enc + _hash 동시 저장
                  - 값이 null/빈값이면 _enc/_hash도 null로 동기화

4. 세션 관리 (Session)
────────────────────────────────────────────────────────────────────────────────

  대상            사용자 인증 세션
  방식            express-session + connect-pg-simple (PostgreSQL 세션 저장소)
  적용 위치       server/index.ts
  세션 서명       ✅ 예 — SESSION_SECRET 환경변수로 쿠키 서명
                  (개발 환경: 하드코딩 기본값, 운영 환경: 필수)
  쿠키 보안       - 운영: secure: true, httpOnly: true, sameSite: "strict"
                  - 개발: secure: false (HTTP 허용)
  저장 위치       PostgreSQL "session" 테이블 (서버측)
  만료            maxAge: 24시간 (86,400,000ms)
  추가 보호       - 중복 로그인 방지 (activeUserSessions Map)
                  - 세션 캐시 (60초 TTL)
                  - 세션 touch 스로틀링 (5분 간격)
                  - 자동 세션 정리 (pruneSessionInterval: 15분)
  비고            - 쿠키에는 세션 ID만 저장 (connect.sid)
                  - 세션 데이터(userId, role 등)는 서버측 DB에만 존재

5. Solapi SMS API 인증
────────────────────────────────────────────────────────────────────────────────

  대상            SMS 발송 API 요청 인증
  방식            HMAC-SHA256 서명
  적용 위치       server/routes.ts — createSolapiAuthHeader()
  실제 암호화     ✅ 예 (API 요청 서명)
  동작            HMAC-SHA256(apiSecret, date + salt) → Authorization 헤더 생성
  환경변수        SOLAPI_API_KEY, SOLAPI_API_SECRET, SOLAPI_SENDER
  비고            - 매 요청마다 새로운 salt(32바이트 랜덤) 생성
                  - ISO 날짜 + salt를 HMAC 서명

6. SMTP 이메일 인증
────────────────────────────────────────────────────────────────────────────────

  대상            이메일 발송 SMTP 인증 정보
  방식            환경변수 참조 (SMTP_PASSWORD)
  적용 위치       server/hiworks-email.ts — initializeEmailTransporter()

  비고            - SMTP 비밀번호는 환경변수로 관리 (코드에 하드코딩 없음)
                  - TLS/SSL로 이메일 서버 연결 암호화

7. Object Storage (파일 업로드/다운로드)
────────────────────────────────────────────────────────────────────────────────

  대상            파일 업로드/다운로드 URL
  방식            Presigned URL (서명된 임시 URL)
  적용 위치       server/replit_integrations/object_storage/objectStorage.ts
                  — signObjectURL()
  실제 암호화     ✅ 예 (URL 서명 — GCS HMAC 기반)
  업로드 TTL      15분 (900초)
  다운로드 TTL    60분 (3600초)
  비고            - 클라이언트가 직접 Object Storage에 PUT/GET
                  - 서버는 서명된 URL만 발급, 파일 데이터 미경유
                  - 파일 자체는 암호화되지 않음 (저장소 레벨 암호화에 의존)

8. API 응답 보호 (데이터 제거/필터링)
────────────────────────────────────────────────────────────────────────────────

  대상            API JSON 응답에서 민감 데이터 제거
  방식            응답 미들웨어 + 구조분해 할당
  적용 위치       server/routes.ts — stripPiiFromResponse(), res.json 오버라이드
  항목:

  ┌───────────────────────┬───────────────────────────────────────────────────┐
  │ 제거 대상              │ 처리 방식                                         │
  ├───────────────────────┼───────────────────────────────────────────────────┤
  │ password              │ 라우트별 { password, ...rest } 수동 제거           │
  │ *Enc (암호화 컬럼)     │ res.json 미들웨어 — 재귀적 자동 제거               │
  │ *Hash (해시 컬럼)      │ res.json 미들웨어 — 재귀적 자동 제거               │
  │ attachments (사용자)   │ 사용자 목록 조회 시 제거 (데이터 크기 절감)          │
  └───────────────────────┴───────────────────────────────────────────────────┘

  비고            - _enc/_hash 제거는 모든 중첩 깊이에 대해 재귀적 적용
                  - password 제거는 라우트별 수동 처리 (누락 가능성 존재)

10. PII 백필 스크립트
────────────────────────────────────────────────────────────────────────────────

  대상            기존 평문 데이터 → 암호화 마이그레이션
  방식            서버 시작 시 자동 실행
  적용 위치       server/backfill-pii.ts — runPiiBackfill()
                  server/index.ts — 서버 시작 후 호출
  동작            - _enc 컬럼이 NULL인 레코드만 처리 (멱등성 보장)
                  - 평문 값을 읽어 AES-256-GCM 암호화 후 _enc 컬럼 저장
                  - 해시 대상 필드는 SHA-256 해시도 함께 생성
  비고            - PII_ENCRYPTION_KEY 미설정 시 실행되지 않음
                  - Users 42명 + Cases 40건 백필 완료 (약 35초)
