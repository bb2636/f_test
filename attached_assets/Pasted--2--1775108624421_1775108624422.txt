종합진행관리 > 상세보기(팝업) > 진행단계 탭에 아래 2가지 기록이 보이도록 수정해줘.

중요:
- 추측해서 임의로 넣지 말고, 실제 진행단계 이력 데이터가 어디서 생성/저장/표시되는지 먼저 찾은 뒤 수정
- 기존 진행단계 기록 방식과 같은 흐름으로 맞춰서 추가
- 단순 화면 문구 하드코딩 금지
- 가능하면 기존 이력/로그 시스템에 자연스럽게 연결
- 결과는 한국어로 정리

--------------------------------------------------
수정 대상
--------------------------------------------------

화면 위치:
- 종합진행관리
- 상세보기(팝업)
- "진행단계" 탭

현재 요청사항:
1. "발생일자 기록" 추가
2. "인보이스 추가 발송 내용" 기록 추가
   (청구서 발송 이력 관리용)

즉, 진행단계 탭에서 기존 단계 변경 이력처럼
아래 내용도 이력으로 확인 가능해야 함.

--------------------------------------------------
요구사항 1
발생일자 기록 추가
--------------------------------------------------

목표:
- 진행단계 탭에서 "발생일자" 관련 변경/입력 내역이 기록되도록 해줘.

먼저 확인할 것:
1. 발생일자가 어느 테이블/컬럼/API에서 관리되는지
2. 발생일자가 생성만 되는지, 수정도 되는지
3. 현재 진행단계 이력은 어떤 방식으로 쌓이는지
   - 별도 history 테이블
   - memo/log/activity 테이블
   - 상태 변경 시 문구 생성
   - API 호출 시 이력 insert
4. 발생일자 변경 시 이력을 남길 적절한 지점이 어디인지

반영 방식:
- 발생일자가 등록되거나 수정될 때,
  진행단계 탭 이력에 해당 내용이 보이도록 추가
- 기존 진행단계 이력 포맷과 최대한 동일하게 맞춰줘
- 날짜/시간이 있다면 기존 이력과 동일한 표시 형식 사용

기록 문구 예시:
- 발생일자 등록: YYYY-MM-DD
- 발생일자 변경: YYYY-MM-DD → YYYY-MM-DD

문구는 실제 기존 진행단계 이력 톤앤매너에 맞게 조정 가능하지만,
핵심은 "발생일자 값이 언제 어떻게 기록/변경되었는지" 보이도록 하는 것

--------------------------------------------------
요구사항 2
인보이스 추가 발송 내용 기록 추가
(청구서 발송 이력 관리용)
--------------------------------------------------

목표:
- 인보이스를 추가 발송한 경우,
  진행단계 탭에서 그 추가 발송 이력이 보이도록 해줘.

먼저 확인할 것:
1. 현재 인보이스 발송 기능이 어디에 있는지
2. "추가 발송"과 "최초 발송"을 구분할 수 있는지
3. 발송 시점에 어떤 데이터가 남는지
   - 발송일시
   - 발송 대상
   - 발송 금액
   - 순번/차수
   - 메모/내용
4. 기존 진행단계 탭에 인보이스 발송 완료 이력이 이미 있다면,
   그 이력 생성 로직을 재사용/확장할 수 있는지 확인

반영 방식:
- 인보이스 추가 발송이 발생하면,
  진행단계 탭에 "추가 발송 이력"이 남도록 해줘
- 단순히 상태만 바꾸는 게 아니라,
  청구서 발송 이력 관리용으로 확인 가능한 수준의 기록이 필요함

가능하면 포함할 정보:
- 발송일자(또는 일시)
- 추가 발송 여부
- 순번/차수(예: 2차, 3차 등)
- 금액(가능하면)
- 관련 상태 변경 내용

예시 문구:
- 인보이스 추가 발송 완료 (2차, 대물: 1,683,000원)
- 인보이스 추가 발송 완료 (3차, 총동비 100,000원)
- 인보이스 발송 완료 - 청구 상태 변경 완료 (순번: 2번, 대물: 1,683,000원)

위 예시는 참고용이고,
실제 문구는 기존 시스템의 진행단계 이력 문구 스타일과 맞춰줘.

핵심:
- "추가 발송했다"는 사실이 보여야 함
- 가능하면 몇 번째 추가 발송인지와 금액/유형도 보여야 함
- 사용자가 청구서 발송 이력을 진행단계 탭에서 확인할 수 있어야 함

--------------------------------------------------
구현 시 확인할 포인트
--------------------------------------------------

1. 진행단계 탭 데이터 소스 찾기
- 어떤 API로 이력을 불러오는지
- 어떤 테이블/배열에서 렌더링하는지
- 정렬 기준이 무엇인지 (최신순/오래된순)

2. 발생일자 이력 기록 시점
- 등록/수정 API 어디에서 이력을 남겨야 하는지
- 기존 이력 저장 함수가 있으면 재사용

3. 인보이스 추가 발송 이력 기록 시점
- 추가 발송 처리 API/함수에서 이력 insert 가능 여부
- 최초 발송과 추가 발송 구분 조건 확인

4. UI 표시
- 진행단계 탭 기존 스타일 유지
- 날짜 색상, 문구 색상, 줄바꿈, 정렬 기존 방식 최대한 유지
- 하드코딩 금지

--------------------------------------------------
수정 원칙
--------------------------------------------------

- 기존 진행단계 이력 시스템에 맞춰 자연스럽게 추가
- 같은 의미의 기록이 중복 생성되지 않게 주의
- 최초 발송/추가 발송 구분이 가능하도록 구현
- 발생일자도 단순 현재값 표시가 아니라 "기록 이력"으로 남게 할 것
- 기존 기능 깨지지 않게 최소 수정
