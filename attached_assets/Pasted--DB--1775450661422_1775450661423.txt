현재 로그인 장애가 간헐적으로 재발하고 있습니다. 
이번 작업은 단순히 눈앞의 에러를 막는 수준이 아니라, 로그인/세션/캐시/DB 연결 전반에서 추후 동일하거나 유사한 장애가 다시 발생하지 않도록 구조적으로 안정화하는 것이 목적입니다.

아래 요구사항을 모두 반영해서 분석하고 수정해주세요.

[목표]
- 로그인 요청이 절대 무한 대기(hang) 상태에 빠지지 않게 할 것
- DB 연결 불안정, 서버 재시작, 캐시 만료, cold start 상황에서도 로그인/세션 기능이 최대한 정상 동작하게 할 것
- 예외가 발생해도 서버 프로세스가 죽거나 재시작 루프에 빠지지 않게 할 것
- 현재 문제 해결뿐 아니라 추후 발생 가능한 유사 장애까지 예방할 것

[반드시 점검할 항목]
1. 로그인 흐름 전체 추적
- LOGIN ATTEMPT
- getUserByUsername
- verifyPassword
- session read/write
- LOGIN SUCCESS / LOGIN FAILED
각 단계별로 어디서 지연/중단/예외가 발생할 수 있는지 확인하고 로그를 보강할 것

2. 캐시 구조 점검
- getCachedUsers, getCachedCasesRaw 포함 캐시 fetch 함수 전체 점검
- shared pending Promise가 영구 대기 상태로 고착될 수 있는지 확인
- TTL 만료 후 재조회 시 장애가 전체 요청 블로킹으로 번지지 않게 수정
- stale-while-revalidate 패턴 적용 가능 여부 검토
- 캐시 fetch 실패 시 fetch 상태값(usersCacheFetching 등)이 반드시 초기화되도록 보장

3. DB 쿼리 안정성 점검
- 모든 핵심 DB 조회에 timeout 적용
- timeout, connection terminated, cold start, transient failure 발생 시 재시도 또는 fallback 전략 적용
- 전체 유저 조회 대신 로그인에는 단건 조회를 우선 사용하도록 검토
- pool / sessionPool 설정(connectionTimeoutMillis, idleTimeoutMillis, max 등) 점검 및 보완

4. 예외 처리 점검
- warm-up, background refresh, login, session 처리 중 발생하는 Promise rejection이 unhandled rejection이 되지 않게 수정
- try/catch 누락 구간 전부 보완
- 실패 시 서버 크래시 대신 안전하게 degrade 되도록 처리

5. 세션/인증 경로 분리
- 캐시 장애가 로그인 장애로 바로 이어지지 않게 할 것
- 로그인/세션 검증은 가능하면 캐시 의존도를 낮추고 직접 조회 fallback을 둘 것
- 사용자 목록/검색 같은 부가 기능 캐시와 인증 핵심 경로를 분리할 것

6. 서버 시작 시 warm-up 점검
- warm-up 실패가 서버 부팅 실패나 크래시로 이어지지 않게 수정
- warm-up은 백그라운드에서 안전하게 동작하게 하고, 실패해도 서비스 핵심 기능은 유지되게 할 것

7. 관측 가능성(로그/디버깅) 강화
- 각 주요 단계에 구조화된 로그 추가
- timeout, fallback 사용 여부, stale cache 사용 여부, direct DB fallback 여부를 명확히 로그로 남길 것
- 다음 장애 발생 시 로그만 보고도 원인을 추적할 수 있게 할 것

8. 추후 발생 가능한 장애 시나리오까지 사전 점검
아래 시나리오를 기준으로 코드상 취약점을 찾아 선제 수정할 것:
- DB 응답 지연
- DB 연결 끊김
- Neon cold start
- 캐시 TTL 만료 직후 동시 다발 로그인
- 서버 재시작 직후 로그인 몰림
- 세션 저장소 지연
- 오래된 pending Promise 재사용
- background warm-up 실패
- direct DB fallback도 실패하는 경우
- 빈 배열/빈 객체 반환 때문에 정상 사용자가 없는 사용자로 처리되는 경우

[출력 방식]
1. 먼저 현재 구조에서 장애 재발 가능 지점을 항목별로 정리
2. 그 다음 실제 수정할 파일/함수/로직을 구체적으로 제안
3. 이후 코드 수정
4. 마지막에 아래 형식으로 정리
- 원인
- 재발 가능 지점
- 적용한 방어 로직
- 남아 있는 리스크
- 추가로 권장하는 개선 사항

[중요]
- 임시방편 말고 재발 방지 중심으로 수정할 것
- "로그인만 되게"가 아니라 "장애가 나도 멈추지 않게" 만드는 방향으로 수정할 것
- 기존 기능을 깨지 않도록 영향 범위도 함께 설명할 것
- 가능하면 작은 수정이 아니라 구조적으로 안전한 방향으로 개선할 것
