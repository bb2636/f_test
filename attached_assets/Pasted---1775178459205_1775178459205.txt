중요:
- 추측해서 화면 문구만 바꾸지 말고, 실제 진행단계 이력/문구 생성 로직을 먼저 찾아서 수정
- 기존 손해방지비용 / 대물복구비용 표시 로직은 유지
- 오직 "선견적" 케이스에서만 예외적으로 문구가 바뀌어야 함
- 결과는 한국어로 정리

--------------------------------------------------
수정 대상 화면
--------------------------------------------------

- 종합진행관리
- 상세보기 팝업
- 진행단계 탭

현재 예시 문구:
- 인보이스 발송 완료 - 청구 상태로 변경 (손해방지비용: 0원, 대물복구비용: 0원)

--------------------------------------------------
수정 요구사항
--------------------------------------------------

기존에는 진행단계 탭에서 인보이스/청구 관련 문구를 표시할 때
항상 아래처럼 손해방지비용, 대물복구비용 기준으로 보여주고 있는 것으로 보임:

- 손해방지비용: n원
- 대물복구비용: n원

이걸 아래 조건일 때만 예외 처리해줘.

### 예외 적용 조건
- 복구방식 또는 복구 유형이 "선견적 요청" / "선견적" 관련 케이스이고
- 진행상태가 "출동비청구(선견적)" 인 경우

위 조건을 만족할 때는,
기존의
- 손해방지비용
- 대물복구비용

표시를 하지 말고 아래처럼 바꿔줘.

### 변경 후 표시 문구
- 출동비(선견적): 100,000원

즉, 진행단계 문구에서
기존:
- (손해방지비용: 0원, 대물복구비용: 0원)

대신

변경:
- (출동비(선견적): 100,000원)

으로 보이게 해줘.

--------------------------------------------------
핵심 조건 정리
--------------------------------------------------

### 선견적 케이스일 때만 변경
다음과 같은 경우에만 변경:
- 복구방식이 선견적 요청
또는
- 복구유형/복구방식이 선견적으로 판단되는 경우
그리고
- 진행상태가 "출동비청구(선견적)" 인 경우

### 기존 로직 유지
아래 경우는 절대 기존 로직 건드리지 말 것:
- 손해방지비용(손방) 케이스
- 대물복구 케이스
- 일반 인보이스 발송/청구 상태 변경 케이스

즉,
손방이나 대물복구일 경우에는 지금처럼 그대로:
- 손해방지비용
- 대물복구비용
표시 유지

구현 시 확인할 것
--------------------------------------------------

1. 진행단계 탭 문구가 어디서 만들어지는지 찾기
- 프론트에서 조합하는지
- 서버에서 문구를 내려주는지
- 이력 저장 시점에 문구를 만들어 저장하는지

2. 아래 값들이 어디에 저장/판단되는지 확인
- 복구방식
- 복구유형
- 진행상태
- 손해방지비용
- 대물복구비용
- 출동비(선견적) 관련 값

3. 출동비(선견적) 금액은 고정값으로 100,000원 표시
- DB 값을 따로 읽는 구조가 아니면
  이번 요구사항에 한해서 고정 문구로 표기
- 단, 실제 코드상 선견적 출동비 필드가 있으면 그 구조도 같이 확인해줘

문구 처리 방식
--------------------------------------------------

조건 만족 시 예시 문구:
- 인보이스 발송 완료 - 청구 상태로 변경 (출동비(선견적): 100,000원)

조건 불만족 시 기존 유지:
- 인보이스 발송 완료 - 청구 상태로 변경 (손해방지비용: 0원, 대물복구비용: 0원)
