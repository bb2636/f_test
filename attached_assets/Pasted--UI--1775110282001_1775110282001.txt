종합진행관리 탭 / 사용자 계정 관리 탭 UI 및 권한위임 기능을 아래 요구사항대로 수정해줘.

중요:
- 먼저 실제 테이블 컴포넌트, 컬럼 정의, 버튼 렌더링, 권한관리 로직을 찾아서 구조를 파악한 뒤 수정
- 하드코딩으로 화면만 맞추지 말고 공통 컬럼/셀 스타일 기준으로 정리
- 종합진행관리와 사용자 계정 관리 탭의 정렬/아이콘 스타일은 최대한 통일
- 권한위임은 실제 권한 변경 기능까지 포함
- 결과는 한국어로 정리

--------------------------------------------------
1. 종합진행관리 탭 수정
--------------------------------------------------

### 헤더 정렬
- 모든 헤더는 가운데 정렬로 수정

### 목록 내용 정렬
- "주소" 값만 왼쪽 정렬
- "승인금액" 값만 오른쪽 정렬
- 나머지 모든 값은 가운데 정렬

### 헤더명 변경
- 일부 헤더 이름 변경 필요
- 현재 코드에서 "메모", "상세보기" 관련 헤더 텍스트를 찾아 실제 요구에 맞게 변경
- 기존 컬럼 의미와 충돌 없게 확인 후 반영

### 돋보기 아이콘 버튼 위치 조정
- 자세히보기 돋보기 아이콘이 세로선(border)과 너무 붙어 있음
- 아이콘 버튼을 세로선에서 약간 띄워서 여백 조정
- 버튼이 답답해 보이지 않도록 padding / margin / justify 방식 점검

### 승인금액 열 너비 조정
- "승인금액" 열 너비를 지금보다 조금 더 넓혀줘
- 금액이 줄바꿈되거나 답답해 보이지 않게 조정
- 전체 테이블 균형도 함께 확인

--------------------------------------------------
2. 사용자 계정 관리 탭 수정
--------------------------------------------------

### 헤더 정렬
- 모든 헤더는 가운데 정렬

### 목록 내용 정렬
- "이메일주소"와 "ID" 값만 왼쪽 정렬
- 나머지 값은 모두 가운데 정렬

### 헤더명 및 아이콘 변경
- 일부 헤더 이름 변경 필요
- "요청" → "상세보기"로 변경
- 자세히보기는 텍스트 버튼이 아니라 돋보기 아이콘 버튼으로 변경
- 종합진행관리 탭과 동일한 스타일/크기/간격/접근성으로 맞춰줘
- aria-label 또는 tooltip 유지

--------------------------------------------------
3. 사용자 계정 관리 탭 - 관리자위임 열 삭제 및 권한위임 기능 이동
--------------------------------------------------

현재 요구사항:
- 헤더의 "관리자위임" 열은 삭제
- 대신 "계정생성" 아이콘 바로 아래에 "권한위임" 버튼/아이콘을 따로 만들어 기능 부여

먼저 확인할 것:
1. 현재 관리자위임 기능이 이미 있는지, 없으면 새로 구현해야 하는지
2. "계정생성" 아이콘/버튼이 어디에 렌더링되는지
3. 사용자/관리자 권한 구조가 DB/백엔드에서 어떻게 관리되는지
4. SuperUser 권한이 어떤 필드/role/value로 관리되는지

--------------------------------------------------
4. 권한위임 기능 상세 요구사항
--------------------------------------------------

### 진입 방식
- 사용자 계정 관리 탭 상단 또는 계정생성 아이콘 바로 아래 영역에
  "권한위임" 버튼/아이콘 추가
- 위치는 계정생성과 자연스럽게 묶이되, UI가 복잡해 보이지 않게 정리

### 팝업 1: 위임 대상 선택
권한위임 버튼 클릭 시 팝업 오픈

팝업 내용:
- 위임 가능한 멤버 목록 표시
- 대상은 “관리자” 목록에서만 선택 가능
- 선택 방식은 라디오버튼 (1명만 선택 가능)

확인할 것:
- 관리자 목록의 기준이 무엇인지
- 비활성/삭제/권한 없는 계정 제외 필요한지
- 현재 로그인한 본인은 선택 대상에서 제외할지 여부 검토
  (기본적으로는 본인 제외가 자연스러움. 실제 정책 확인 후 반영)

### 팝업 하단 버튼
- "권한위임" 버튼 배치

### 팝업 2: 최종 확인
팝업 하단 "권한위임" 버튼 클릭 시
다음 확인 팝업 표시:

문구:
- "SuperUser권한을 위임하시겠습니까?"

버튼:
- 취소
- 확인

### 최종 동작
- "확인" 클릭 시, 앞에서 선택한 멤버에게 SuperUser 권한이 넘어감

--------------------------------------------------
5. 권한위임 정책
--------------------------------------------------

핵심 정책:
- 현재 SuperUser가 선택한 관리자에게 SuperUser 권한을 넘김
- 이 권한을 다시 받아오려면, 새로 권한을 받은 멤버가 동일한 방식으로 다시 위임해야 함
- 즉, 단순 복사/추가가 아니라 “권한 이전” 개념인지 확인 필요

먼저 반드시 확인할 것:
1. SuperUser가 여러 명 존재 가능한 구조인지
2. 권한위임 시:
   - 기존 SuperUser 권한은 제거되고
   - 새 대상에게만 부여되는지
3. audit/log/history를 남겨야 하는지
4. 본인이 본인에게 위임하는 경우 차단할지
5. 권한위임 가능한 사용자 조건 (관리자만 가능) 확인

권장 구현 방향:
- “권한 복수 부여”가 아니라 “SuperUser 단일 이전” 정책인지 먼저 실제 구조 확인
- 단일 이전 정책이면 트랜잭션으로 안전하게 처리
- 기존 SuperUser 권한 제거 + 신규 부여를 원자적으로 처리

--------------------------------------------------
6. 백엔드 / 보안 / 권한 체크
--------------------------------------------------

반드시 확인할 것:
- 권한위임 기능은 아무나 실행하면 안 됨
- 현재 로그인 사용자가 SuperUser일 때만 실행 가능하도록 제한
- API에서도 서버 측 권한 검증 필수
- 프론트 숨김만으로 처리 금지

추가 권장:
- 권한위임 성공 시 성공 메시지 표시
- 실패 시 에러 메시지 표시
- 가능하면 누가 누구에게 언제 위임했는지 로그 남기기

--------------------------------------------------
7. UI/정렬 공통 수정 원칙
--------------------------------------------------

- 테이블 헤더 정렬은 컬럼별 className 또는 공통 컬럼 렌더링 함수에서 정리
- 셀 정렬도 컬럼별로 명확히 구분
- 종합진행관리 / 사용자 계정 관리 탭의 돋보기 아이콘 스타일 통일
- 세로선과 아이콘 간격은 padding/margin으로 자연스럽게 조정
- 승인금액 열 너비 확장 시 다른 컬럼이 과도하게 찌그러지지 않도록 전체 균형 점검
